# Stage5 Node Worker 获取边界

本批在 r3 上补齐正式 Node Worker 的一次性获取边界。真实 DOM 解析尚未验证，r3 的 data-entity-id 等只属于合成协议，不能用于真实来源。源码没有采集 CLI、调度器、公共页面引用或数据库写入。

## 使用边界

`apps/sync-worker/src/sources/yuc-fetch.ts` 的 YucNodeAcquisition 默认关闭，注入 wire。2026-10-04 增加显式进程内配置：`createNodeYucWire({ connectionMode: "approved-proxy" | "direct" })`。缺少或无效模式立即拒绝，普通启动不调用获取模块。唯一目标 https://yuc.wiki/202610/。

代理模式保留固定批准入口 http://127.0.0.1:10090，并显式清空 NO_PROXY；直连模式使用专用 Node24.5+ 标准 https.Agent，`proxyEnv: {}`，不继承环境代理。不允许自动回退或切换，不修改环境、CA 或全局 Agent，严格证书/主机名校验保持 Node 默认行为。应用直连配置不证明上游无透明代理，也不能证明历史代理故障恢复。

依据：[Node官方内置代理说明](https://nodejs.org/docs/latest-v24.x/api/http.html#built-in-proxy-support)。本机Node24.16.0标准Agent空proxyEnv已离线核对；没有自建TLS钩子。只额外保留白名单Node错误码及已收到的HTTP状态，不暴露错误原文、证书链、凭据或响应正文。

本批预算为每个明确授权的执行会话最多一次调用：20 秒总超时（包括获取及读取）、1 MiB 响应、并发一、零重试、零重定向、零子资源。只有一次请求，因此没有第二次请求的间隔；不能通过重新创建对象绕过会话预算。此类不是长期同步策略或永久限流器，未来同步必须另行授权和设计，不能循环创建对象出网。

来源关闭立即取消在途获取，排队调用再次检查开关与熔断。失败不返回成功空数据、不触碰候选库存；成功只返回内存 HTML 供已批准观察，不自动使用合成解析器冒充真实 Adapter。错误仅暴露固定分类，不输出原始异常文本。
